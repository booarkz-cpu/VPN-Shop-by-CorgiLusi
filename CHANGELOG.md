# Changelog

## 20.0.22 — 2026-09-29

Исправлен сбой свежей VDS-установки при записи Support Pro `.env`: пароль Support Redis теперь создаётся до записи обоих файлов и совпадает в корневом `.env` и `support-pro/.env`. Добавлен тест с `set -u`, не подставляющий эту переменную извне. В [инструкции VDS](docs/ru/VDS_PRODUCTION_20_0_22.md) приведено восстановление после неполной установки v20.0.21 с сохранением ранее созданных секретов.

## 20.0.21 — 2026-09-29

Исправлена индикация доступного обновления в API админки: новая версия предлагается только при корректном теге и паре ZIP/SHA-256, соответствующих тегу; скачивающий скрипт проверяет адрес обоих активов. Обновлены README, указатель документации и инструкция VDS с командой для v20.0.21. Старые маршруты отмечены как история. Живые платежи требуют полного staging E2E v2.

## 20.0.20 — 2026-09-28

Автообновление сверяет `APP_VERSION` внутри проверенного ZIP с тегом релиза до запуска обновления. Распаковщик заранее отклоняет дублирующиеся пути и специальные файлы, чтобы неоднозначный ZIP не заменил один файл другим. Добавлены регрессионные проверки отказа и успешного выпуска. Это выпуск исходников; для допуска production платежей требуется полный staging E2E v2.

## 20.0.19 — 2026-09-28

Сохранение вложенных файлов окружения при восстановлении, проверка архива отката до остановки сервисов, обновление GitHub Actions и исправление пропуска устаревшей публикации мобильных пакетов. Автообновление теперь сверяет имя ZIP и контрольной суммы с тегом релиза, а строку SHA-256 — с именем ZIP. [Заметки выпуска](.github/release-v20.0.19.md). Production платежи требуют staging E2E v2; реальный VDS и кассы не проверены этим выпуском.

## Неизданные исправления — 2026-09-28

- **GitHub Actions:** workflow CI, Docker, мобильных пакетов, публикации и развёртывания переведены на версии официальных GitHub и Docker actions с Node.js 24; Linux runner закреплён на Ubuntu 24.04. Устранены предупреждения о Node.js 20 и предстоящей смене `ubuntu-latest`. Проверка итоговых заданий выполняется в GitHub Actions после публикации.
- **Mobile packages:** сборки для коммита, не совпадающего с тегом `v20.0.15` или текущей веткой `main`, остаются в артефактах workflow; шаг публикации выводит причину пропуска и завершается без ложной ошибки. Для нового production-выпуска требуются отдельный тег, успешный CI и постоянная подпись Android/iOS.
- **Восстановление:** ручной откат и аварийный откат обновления сохраняют все обычные вложенные `.env` и `.env.*` из установленного дерева, а не только `support-pro/.env`. Добавлена регрессия для `backend/.env.local`; восемь тестов восстановления проходят.
- **Откат:** перед остановкой сервисов архив проверяется на опасные пути, ссылки, специальные записи и попадание `.env`, `.git` или `.rollback`. Раньше проверялась только читаемость gzip/tar: подготовленный вручную архив мог перезаписать секреты либо содержать ссылки за пределы дерева приложения. При отказе установка остаётся работающей; архивы со ссылками нужно пересоздать без них.
- **Обновление:** копирование проверенного релиза исключает вложенные `.env*`, `.git` и `.rollback` на всех уровнях. Раньше фильтр покрывал только корень архива, из-за чего релиз мог заменить локальный `support-pro/.env`.
- **Проверки:** добавлены регрессии отката для защищённых файлов и символических ссылок, а также проверка сохранения вложенного файла окружения при обновлении. Локально проходят 8 тестов `test_v2018_recovery.py`, `compileall`, `bash -n` и `git diff --check`.

Ограничение проверки: полный CI, Docker-сценарии и сборки клиентов здесь не выполнены: `pytest` не установлен, npm offline не содержит все пакеты. Эти исправления не означают допуска реальных платежей; по-прежнему требуется полный staging E2E v2.

## 20.0.18 — 2026-09-28

Исправлен установщик: домен кабинета больше не перезаписывается пустым CORS. Ручной rollback до остановки сервисов проверяет наличие дампа БД и целостность архива, сохраняет локальный `.git` и файлы окружения, не кладёт вложенные `.env` в архив. Автообновление удаляет распакованный релиз после завершения. Резервное копирование пропускает каталог `.rollback`; восстановление использует порт БД из `DATABASE_URL`. Добавлены проверки восстановления и обновления. Живые платежи по-прежнему требуют staging E2E v2.

## 20.0.17 — 2026-09-28

Корректирующий выпуск исходников: исправлены имена вложений релиза и проверка их соответствия версии. Содержит все исправления и инструкцию VDS из 20.0.16. Тег 20.0.16 сохраняется для истории, но его ZIP и SHA-256 имеют старое имя; для новой установки используйте 20.0.17.

## 20.0.16 — 2026-09-28

Исправлен запуск VDS: установщик теперь исполняется из каталога исходников, создаёт оба файла окружения с обязательными секретами Support Pro, проверяет домены и сохраняет SSH-порт текущей сессии перед включением firewall. Непустые параметры касс при автоматической установке больше не сбрасываются. Исправлена CSP Telegram Mini App и проверка готовности БД/Redis через `/health/ready`. Обновление больше не зависит от `pytest` на хосте, прерывается при ошибке дампа и сохраняет секреты Support Pro и image pins при откате. Добавлена подробная инструкция VDS от подключения по SSH до backup, обновления и диагностики: [docs/ru/VDS_PRODUCTION_20_0_17.md](docs/ru/VDS_PRODUCTION_20_0_17.md). Живые платежи остаются закрыты до полного staging E2E v2. Native mobile остаётся версии 2.15.0; новая подпись APK/IPA этим выпуском не заявляется.

## 20.0.15 / Mobile 2.15.0 — 2026-09-28

Защищено хранение native-токенов и блокировка приложений; исправлены recovery login, ранний PKCE-отказ и конкурентная регистрация; усилены production secrets, Support sessions, инфраструктурный RBAC и валидация конфигурации. Backup/restore используют приватные временные каталоги. Публикация native production требует успешного CI и постоянной подписи владельца, без подмены debug/unsigned сборками. [Аудит](docs/ru/AUDIT_20_0_15.md) · [Обновление и подпись](docs/ru/PRODUCTION_20_0_15.md).

## Mobile 2.14.1 — 2026-09-27

Согласованы версии четырёх native-клиентов, build 2141 и User-Agent; сохранён PKCE-вход для backend 20.0.14.
