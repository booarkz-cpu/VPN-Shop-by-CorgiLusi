# Аудит 20.0.15 и мобильные клиенты 2.15.0

Дата: 2026-09-27. База аудита: `dfb8f098962531cac292c834b9d10fa5e334bfd8`.

Проверены исходники backend API, платежных обработчиков и блокировок, аутентификации/RBAC, backup/restore, Support Pro, веб-клиентов, четырёх native-клиентов, конфигурации Compose и GitHub Actions. Использованы ручное чтение критических путей, Bandit, регрессионные тесты, PostgreSQL-конкурентные проверки, аудит зависимостей и сборки CI. Это проверка репозитория: DAST рабочего VDS, реальные платежи, эксплуатация на физических Android/iPhone и независимый пентест не выполнялись. Аудит не доказывает отсутствие всех возможных ошибок.

## Подтверждённые проблемы и исправления

| Риск | Проблема | Исправление / проверка |
| --- | --- | --- |
| High, мобильные сессии | Bearer-токены хранились в Android SharedPreferences / iOS UserDefaults открытым текстом | Android AES-256-GCM с ключом Android Keystore; API origin включён в AAD. iOS Keychain `WhenUnlockedThisDeviceOnly`, запись связана с API origin. Старые plaintext-токены удаляются, требуется новый вход |
| High, блокировка приложения | Ошибка/недоступность биометрии открывала сохранённую сессию | Ошибки теперь оставляют экран заблокированным. Повторный вход доступен после выхода. При уходе в фон блокировка включается снова; Android запрещает снимки экрана, iOS скрывает содержимое в неактивной сцене |
| High, конфигурация | Production пропускал короткие пароли администратора и фактический пароль DATABASE_URL; старый JWT-ключ мог оставаться слабым | Минимум 12 символов ADMIN_PASSWORD, 16 — пароль DATABASE_URL, 32 — APP_SECRET и непустой APP_SECRET_PREVIOUS; известные placeholder-префиксы отклоняются |
| High, Support Pro | Не было проверки стойкости SESSION_SECRET при запуске | Пустой/короткий/placeholder SESSION_SECRET отклоняется, минимум 32 символа |
| Medium, восстановление входа | Генератор выдавал 10-символьные recovery-коды, LoginIn допускал максимум 8, веб-форма — только 6 цифр | API и форма принимают 10 символов. Тест проверяет успешный вход с реально сгенерированным кодом и отказ при его повторном использовании |
| Medium, logout | Native-клиенты очищали только локальный токен; admin logout не читал Bearer | Все клиенты запрашивают серверный отзыв; admin endpoint принимает Bearer. При сбое сети локальный выход сохраняется, отзыв на сервере не заявляется подтверждённым |
| Medium, native API | Неверный PKCE challenge отклонялся после создания аккаунта/сессии и commit | Проверка challenge выполняется до записи. Три регрессионных сценария подтверждают отсутствие обращений к БД при неверном challenge |
| Medium, регистрация | Одновременные регистрации одного email могли вызвать unique violation и HTTP 500 | Транзакционная PostgreSQL-блокировка по нормализованному email. Конкурентный тест: один успех, один 409, одна запись пользователя |
| Medium, RBAC | Оператор с manage_users мог менять настройки безопасности и ставить инфраструктурные действия в очередь | Конфигурация v6 требует `security.manage`, orchestrator/provision — `provision_nodes`; это права администратора |
| Medium, настройки | Строки вместо чисел/булевых значений и неверные пороги ломали расчёт capacity/orchestrator | Проверка типов и диапазонов перед записью; некорректные значения дают 422 |
| Medium, Support Pro | Сессия не проверяла соответствие operator_id и не имела абсолютного срока на сервере | Проверяется владелец LoginSession; срок ограничен 8 часами независимо от обновления cookie. Есть тесты чужой и истёкшей сессии |
| Medium, backups | Временные каталоги создавались с обычными правами, один путь был предсказуемым | Все четыре операции используют `mkdtemp`, случайный путь и режим 0700; действующая очистка сохранена |
| Functional, operations | Rollback API требовал несуществующее право `write`, поэтому был недоступен всем | Используется admin-only `security.manage`, блокировка записи Deployment и audit-событие. Это изменение записи control plane, не самостоятельный откат Docker/VDS |
| Release integrity | Публикация мобильных файлов не требовала завершения общего CI, debug/unsigned файлы могли восприниматься как production | Publication ждёт успешный CI и соответствующий source tag. Production принимает только release APK с проверенной недебажной подписью и Apple-signed IPA; отсутствие ключей фиксируется как blocked |

## Проверки

- Backend: весь pytest-набор; отдельные проверки recovery-кодов, раннего PKCE-отказа, production credentials, существования разрешений, запрета инфраструктурных действий оператору и типов конфигурации.
- PostgreSQL CI: миграции и конкуренция регистрации, платежей/возвратов, provider event claim и restore approval.
- Support Pro: весь набор, включая team isolation, SSO, SSRF, session secret/owner/lifetime.
- Android: Debug и Release сборки обоих приложений; проверка build 2150, версии 2.15.0 и отсутствия debuggable у Release. Криптография Keystore и биометрия требуют дополнительного теста на физическом устройстве.
- iOS: оба приложения собираются для iphoneos и Simulator. Ветка Apple-подписи требует ключей владельца и до их предоставления не считается проверенной.
- Web: typecheck и production builds; Python/JavaScript зависимости проверяются CI; контейнеры запускаются с проверкой UID, Redis AUTH и writable volumes.
- Bandit: находки проверяются вручную. Временные пути исправлены. Вызов Paramiko остаётся ожидаемым medium finding: динамические строки экранированы `shlex.quote`, числовые порты преобразуются и проверяются; SSH host key проверяется. Наличие SSH provisioning не трактуется как произвольное исполнение от непривилегированного пользователя.

## Что не следует считать готовым production

1. Подписанные native-пакеты требуют постоянного Android keystore / Apple Developer identity. Состояние публикации находится в `mobile-production-status.json` релиза. `blocked_*` означает, что устанавливаемого production-пакета этой платформы нет.
2. Полный staging E2E v2 платежей ещё не реализован. Этот релиз не снимает payment gate; живые платежи остаются закрытыми.
3. Native приложения управляют магазином и подписками. Встроенный VPN forwarding engine не реализован; используется импорт подписки во внешний VPN-клиент.
4. DNS, CORS, ingress, секреты, backup restore и публичные порты конкретного VDS должны быть проверены на вашем окружении. Репозиторные тесты этого не заменяют.
