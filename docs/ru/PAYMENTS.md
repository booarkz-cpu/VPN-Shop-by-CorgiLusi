# Подключение платёжных систем

Магазин создаёт счёт у провайдера и выдаёт подписку только после проверки, что провайдер подтвердил ту же сумму, валюту и номер заказа. Вебхук сам по себе подписку не включает, пока сверка со шлюзом не прошла.

Живые платежи дополнительно закрыты флагом `payments.production_gate`. Пока он выключен, `POST /api/payments/create` отвечает `503`, даже если ключи заполнены. Песочница этот флаг не использует и на production запрещена. Сначала поднимите магазин по [DEPLOYMENT.md](DEPLOYMENT.md).

## 1. Выбрать провайдера

Заполните только те ключи, которыми будете пользоваться. Пустой ключ выключает провайдера из маршрута.

| Провайдер | Обязательные переменные | Вебхук |
| --- | --- | --- |
| YooKassa | `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_WEBHOOK_IP_ALLOWLIST` | `POST https://API_DOMAIN/api/webhooks/yookassa` |
| Platega | `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` | `POST https://API_DOMAIN/api/webhooks/platega` |
| RollyPay | `ROLLYPAY_API_KEY`, `ROLLYPAY_SIGNING_SECRET` | `POST https://API_DOMAIN/api/webhooks/rollypay` |
| Stripe | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | путь вебхука Stripe в API |
| PayPal | `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_WEBHOOK_ID` | путь вебхука PayPal в API |
| Крипто-шлюз | `CRYPTO_GATEWAY_URL`, `CRYPTO_GATEWAY_KEY` | по договору шлюза |

`YOOKASSA_API_URL` по умолчанию `https://api.yookassa.ru`. `PLATEGA_API_URL` — `https://app.platega.io`. `ROLLYPAY_API_URL` — `https://rollypay.io`. Меняйте их только если провайдер дал другой адрес. Адрес проверяется как публичный URL.

Возвраты Platega и RollyPay требуют отдельные URL: `PLATEGA_REFUND_URL`, `PLATEGA_REFUND_STATUS_URL`, `ROLLYPAY_REFUND_URL`, `ROLLYPAY_REFUND_STATUS_URL`. Без них возврат этого провайдера завершится ошибкой конфигурации, а не молчаливым успехом.

`ROLLYPAY_TEST_MODE=true` передаёт провайдеру признак тестового счёта. Это режим кассы RollyPay, а не песочница магазина.

## 2. YooKassa

1. В кабинете ЮKassa возьмите shop id и секретный ключ.
2. Запишите их в `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
3. В уведомлениях укажите URL `https://API_DOMAIN/api/webhooks/yookassa` и событие успешной оплаты.
4. В `YOOKASSA_WEBHOOK_IP_ALLOWLIST` перечислите сети, с которых ЮKassa присылает уведомления, через запятую. Пустой список отклоняет все уведомления. Магазин смотрит на адрес ближайшего прокси, а не на адрес, который клиент сам написал в `X-Forwarded-For`.
5. Перезапустите backend и worker: `docker compose up -d`.

Чек с email покупателя уходит, только если у пользователя заполнен email.

## 3. Platega

1. Запишите merchant id и секрет.
2. В кабинете Platega укажите вебхук `https://API_DOMAIN/api/webhooks/platega`.
3. Уведомление должно приходить с заголовками `X-MerchantId` и `X-Secret`, совпадающими с значениями в `.env`. Чужой секрет отклоняется.
4. Перед выдачей магазин ещё раз читает транзакцию у Platega и сверяет сумму и `payload` с номером заказа.

## 4. RollyPay

1. Запишите API-ключ и секрет подписи.
2. Укажите вебхук `https://API_DOMAIN/api/webhooks/rollypay`.
3. Уведомление обязано содержать `X-Signature` (HMAC-SHA256 тела) и `X-Timestamp`. Метка старше пяти минут отклоняется. Без метки подпись тоже отклоняется: иначе перехваченное уведомление можно было бы прислать снова.
4. Перед выдачей магазин читает платёж у RollyPay и сверяет сумму и `order_id`.

## 5. Открыть боевые платежи

Ключей недостаточно. Нужен успешный полный staging: счёт, вебхук, выдача, повтор того же вебхука, возврат. Результат должен быть не старше 24 часов.

В панели, с ролью `admin` (право `security.manage`), откройте раздел проверки тестового контура, сохраните staging-ключи, которые не совпадают с боевыми ключами из `.env`, и дождитесь статуса прохождения. Затем включите боевые платежи. Запрос `POST /api/admin/payments/production-gate` с `{"enabled": true}` делает то же самое и отвечает `409`, если проверка устарела или не полная.

Выключить приём можно сразу: `{"enabled": false}`.

Пока флаг выключен, покупатель видит отказ «Реальные платежи временно заблокированы». Это ожидаемо.

## 6. Проверить один платёж

1. Создайте тариф с маленькой ценой.
2. Зарегистрируйте тестового покупателя в кабинете.
3. Оплатите тариф выбранной кассой.
4. Вернитесь в кабинет. В центре биллинга статус платежа `paid`, выдача `completed`.
5. Откройте ссылку подписки. Она должна быть `https://` адресом Remnawave, а не `sandbox://`.
6. Пришлите тот же вебхук ещё раз. Вторая доставка не продлевает срок.
7. Оформите возврат из панели. Подписка должна уйти в отзыв доступа, а повторный успешный вебхук не должен выдать её снова.

## 7. Автопродление

`AUTO_RENEW_ENABLED=true` позволяет сохранить способ оплаты ЮKassa и списывать следующий период. Песочница рекуррентные списания не выполняет. Не включайте автопродление, пока ручной возврат на staging не прошёл.

## 8. Чего не делать

- Не ставьте `PAYMENTS_SANDBOX=true` на домене, где уже есть покупатели. Процесс с `APP_ENV=production` откажется стартовать, и это правильная остановка.
- Не копируйте боевые ключи в форму staging. Сохранение отклоняет ключи, которые совпали с `.env`.
- Не открывайте порт PostgreSQL, чтобы «поправить» флаг в базе вручную на публичном сервере. Используйте метод панели.

## 9. Apple, Google, Stripe и PayPal

`MOBILE_STORE_PRODUCTS` — JSON-объект, где ключ это id продукта в App Store или Google Play, а значение это id тарифа магазина. Пример: `{"com.shop.month": 1}`. Пустая переменная отклоняет `POST /api/payments/mobile/verify`. Чек Apple без `transactionId` и без ключей App Store Server API тоже отклоняется. Чек Google Play годится только при `SUBSCRIPTION_STATE_ACTIVE`, и продукт из ответа Google должен быть в этой карте.

Вебхук Stripe: `POST /api/payments/webhooks/stripe`. Подписка включается, только если `payment_status` равен `paid`, а `amount_total` и валюта совпали с заказом. Сессия, которую покупатель завершил, но ещё не оплатил, подписку не включает.

Вебхук PayPal: `POST /api/payments/webhooks/paypal`. Сумма захвата и валюта должны совпасть с заказом. Чужую сумму магазин не проводит.

Подарочная карта зачисляется на баланс только если её валюта равна `DEFAULT_CURRENCY`.
