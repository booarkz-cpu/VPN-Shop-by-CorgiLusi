# Реальные платежи с ЮKassa: куда нажимать, что вводить и где остановиться

**Для владельца магазина без опыта работы с сервером. Проверено 28.09.2026 по проекту `v20.0.18`, исходникам админки и официальным инструкциям ЮKassa.** Эта инструкция показывает пример с **ЮKassa**. У Stripe, PayPal и других касс свои кабинеты и поля; их кнопки здесь не описаны. Все адреса вида `example.com` замените на собственный домен.

> **Стоп для текущей версии:** в `v20.0.18` ещё нельзя принимать реальные платежи через этот проект. В разделе «Безопасность» кнопка **«Разрешить реальные платежи» отключена прямо в интерфейсе**. Проверка тестового контура записывает `contract_version=1` и `full_e2e=false`, а сервер требует версию 2 и полный успешный результат. Пункты 1–9 позволяют подготовиться. Пункты 10–13 — порядок действий **после выхода нового релиза с настоящим E2E v2**, а не работающая сегодня кнопка. Не меняйте БД и код ради обхода.

## Как пользоваться инструкцией

- **«В браузере»** — откройте Chrome/Firefox на своём компьютере и нажимайте указанные кнопки.
- **«В терминале сервера»** — подключитесь к VDS через PowerShell, Terminal или Termius и вводите команду целиком, затем Enter. Значок `$` копировать не надо.
- **Production** — ваш будущий рабочий магазин. **Staging** — второй сервер для пробных покупок. У них разные домены, базы, боты, Remnawave и ключи ЮKassa.
- Текст `ВАШ-ДОМЕН` означает ваш настоящий домен. Например, если он `vpn.example.com`, адрес API будет `api.vpn.example.com`. Пример `example.com` не заработает как адрес вашего магазина.
- Если получите ошибку, остановитесь на этом пункте. В конце есть таблица «Что проверить». Пароли, токены и содержимое `.env` никому не отправляйте.

## 1. Приготовьте данные на бумаге или в менеджере паролей

| Что записать | Пример для понимания | Откуда взять |
| --- | --- | --- |
| Домен магазина | `vpn.example.com` | Панель регистратора домена |
| IP рабочего VDS | `203.0.113.10` | Панель хостера |
| IP тестового VDS | `198.51.100.10` | Панель хостера |
| SSH-пользователь | `root` или sudo-пользователь | Письмо хостера |
| URL/токен рабочей Remnawave | `https://panel...` | Ваша рабочая панель Remnawave |
| URL/токен тестовой Remnawave | другой URL и токен | Отдельная тестовая панель |
| Email администратора | ваш действующий email | Выбираете сами |
| Два Telegram-бота | рабочий и тестовый | @BotFather |
| ЮKassa | отдельные тестовый и настоящий магазины | Личный кабинет ЮKassa |

Нужны **два независимых VDS** с Ubuntu 24.04 или Debian 12; ориентир из инструкции установки — минимум 2 vCPU, 4 ГБ RAM и 30 ГБ свободного места для каждого. Не используйте один PostgreSQL или одну Remnawave для обеих сред.

## 2. Настройте домены в панели регистратора

**В браузере:** войдите в панель, где куплен домен → откройте раздел с названием **DNS**, **Управление зоной** или **DNS-записи**. Интерфейсы регистраторов различаются; ищите поля «Тип», «Имя/Host», «Значение/IP».

Создайте записи типа **A** для рабочего IP. Если ваша зона — `vpn.example.com`, обычно в поле «Имя» вводят `api`, `admin`, `app`, `cabinet`, `support`. Если панель управляет зоной `example.com`, имена будут `api.vpn`, `admin.vpn` и т. д. Смотрите превью **полного** имени перед сохранением.

| Полное имя | Значение A-записи |
| --- | --- |
| `api.vpn.example.com` | IP рабочего VDS |
| `admin.vpn.example.com` | IP рабочего VDS |
| `app.vpn.example.com` | IP рабочего VDS |
| `cabinet.vpn.example.com` | IP рабочего VDS |
| `support.vpn.example.com` | IP рабочего VDS |
| `api.stage.vpn.example.com` и аналогичные `admin`, `app`, `cabinet`, `support` | IP **тестового** VDS |

Нажмите **«Добавить/Сохранить»** для каждой записи. Если для этих имён есть AAAA-записи, а IPv6 на соответствующем VDS не настроен, удалите неверные AAAA. В панели хостера проверьте, что доступны TCP 80/443 и ваш SSH-порт. Сохраните SSH-порт открытым, чтобы не потерять доступ.

**Проверка в терминале:** `dig +short A api.vpn.example.com` и `dig +short A api.stage.vpn.example.com` должны вернуть **разные** правильные IP. Если `dig` нет, установите `dnsutils` (`sudo apt-get update && sudo apt-get install -y dnsutils`). Не продолжайте, пока записи не заработали.

## 3. Создайте рабочего и тестового Telegram-ботов

**В Telegram:** найдите официальный `@BotFather` → откройте чат → отправьте `/newbot` → введите понятное имя → введите уникальное имя пользователя, которое заканчивается на `bot` → сохраните выданный токен в менеджере паролей. Повторите для **другого** staging-бота. Не публикуйте токен: владелец токена управляет ботом. Порядок `/newbot` описан в [официальной документации Telegram](https://core.telegram.org/bots/features).

Если бот и Remnawave у вас уже настроены, перепроверьте, что их **тестовые** токены относятся ко второму серверу. В инструкции установки для нового магазина приведены остальные проверки: [VDS v20.0.18](VDS_PRODUCTION_20_0_18.md).

## 4. Поставьте рабочий магазин с выключенной кассой

**На компьютере:** откройте PowerShell (Windows), Terminal (macOS/Linux) или Termius. Введите `ssh root@IP_РАБОЧЕГО_VDS` (замените IP и пользователя своими). При первом входе сверяйте отпечаток SSH-ключа с панелью хостера; при вводе пароля символы не отображаются.

**В терминале рабочего VDS:** вводите команды по одной:

```bash
sudo apt-get update
sudo apt-get install -y git ca-certificates curl
cd /opt
sudo git clone --branch v20.0.18 --depth 1 https://github.com/booarkz-cpu/shop-by-boo.git vpn-shop-src
cd /opt/vpn-shop-src
sudo bash deploy/install-vps.sh
```

Установщик будет задавать вопросы. Когда в строке показано значение в скобках, **Enter** принимает предложенное значение. Не нажимайте Enter, если в строке нужен ваш секрет или адрес.

| Вопрос установщика | Что вводить на рабочем сервере |
| --- | --- |
| «Основной домен» | ваш `vpn.example.com`, без `https://` |
| API/админка/Mini App/кабинет/Support Pro | проверьте, что предложенные пять имён совпадают с DNS из пункта 2; если совпали — Enter |
| Email администратора | ваш действующий email |
| Пароль администратора | придумайте уникальный длинный пароль или Enter для случайного; сохраните его |
| `BOT_TOKEN` | токен **рабочего** бота |
| `Remnawave Panel URL` и `Remnawave API token` | **рабочая** панель и её токен |
| «Провайдер (yookassa / platega / rollypay / none)» | введите **`none`** |
| «Дополнительные кассы» | оставьте все ключи пустыми: Enter |
| «Имя бота без @» | имя пользователя рабочего бота, без символа `@` |
| Язык, валюта, часовой пояс | `ru`, `RUB`, `Europe/Moscow`, если это ваши реальные настройки |
| Цены | введите свои цены или оставьте предложенные только для начальной проверки |
| «Автопродление» | `false`, пока не испытан цикл платежа и повторного списания |
| «Песочница платежей без шлюзов» | **`false`**: production не допускает `true` |
| Yandex/VK/S3 и дополнительные поля | заполняйте лишь если реально подключаете; детали — в полной инструкции установки |

После окончания **на рабочем VDS**:

```bash
cd /opt/vpn-shop
sudo docker compose --env-file .env config --quiet
sudo docker compose ps
curl -fsS https://api.vpn.example.com/health/ready
```

Замените `vpn.example.com` вашим доменом. Если `/health/ready` не показывает рабочее состояние, откройте [инструкцию диагностики установки](VDS_PRODUCTION_20_0_18.md), проверьте DNS, порты, сертификат, `sudo docker compose ps` и `sudo docker compose logs --tail=100 backend caddy`. Не публикуйте сырые логи, если в них есть личные данные.

## 5. Войдите в админку и включите 2FA

**В браузере:** откройте `https://admin.vpn.example.com`. На экране «Войти» заполните **Email** и **Пароль** из пункта 4; поле **«Код 2FA»** при первом входе оставьте пустым → нажмите **«Войти»**.

Слева откройте группу **«Безопасность» → «Безопасность»**. Найдите строку **«2FA / TOTP»** → нажмите **«Включить 2FA»**. Экран покажет секрет, ссылку и коды восстановления. Добавьте секрет в приложение-аутентификатор; сохраните коды восстановления **офлайн**, не на общем экране. Введите текущий шестизначный код в поле → нажмите **«Подтвердить»**. Убедитесь, что теперь написано **«2FA / TOTP: ВКЛ»**.

Затем откройте **«Безопасность» → «Администраторы»**, добавьте второго администратора с отдельным email, паролем и ролью **«Администратор»**; войдите под ним и включите 2FA отдельно. Это потребуется для восстановления. В разделе **«Бекапы»** создайте копию и проверьте её, а восстановление испытайте **на отдельном стенде**, не на рабочей базе.

Строка **«Разрешение реальных платежей: ВЫКЛ — заблокировано»** пока правильная. Не пытайтесь включать её.

## 6. Поставьте staging на втором VDS

Откройте **новое** SSH-подключение к IP **тестового** VDS и повторите пункт 4, но в качестве основного домена укажите `stage.vpn.example.com`, тестового бота и тестовую Remnawave. На вопрос про провайдера снова ответьте `none`; `PAYMENTS_SANDBOX` во время установки оставьте `false`.

Установщик сначала задаёт production-окружение. **Только после завершения установки и только на тестовом сервере** отредактируйте `.env`:

```bash
cd /opt/vpn-shop
sudoedit .env
```

В редакторе найдите строку `APP_ENV=production` и замените на `APP_ENV=staging`; найдите `PAYMENTS_SANDBOX=false` и замените на `PAYMENTS_SANDBOX=true`. Сохраните файл и закройте редактор (если открылся nano: Ctrl+O, Enter, Ctrl+X; для другого редактора используйте его собственные команды). Не переносите рабочий `.env` на второй VDS. Затем:

```bash
sudo docker compose --env-file .env config --quiet
sudo docker compose up -d --build
sudo docker compose ps
curl -fsS https://api.stage.vpn.example.com/health/ready
```

**В браузере:** откройте `https://admin.stage.vpn.example.com`, войдите под **тестовым** администратором → слева **«Продажи» → «Тарифы»**. Введите название вроде «Проверка — 1 месяц», положительную цену в рублях → нажмите **«+ Добавить»**. Запишите номер после `#` на карточке: это **ID тестового тарифа**. Создайте отдельного тестового покупателя в staging кабинете `https://cabinet.stage.vpn.example.com`. Проверка магазина через внутреннюю песочницу не является проверкой ЮKassa.

## 7. Создайте тестовый магазин ЮKassa и найдите его ключи

**В браузере:** войдите в [личный кабинет ЮKassa](https://yookassa.ru/). Если аккаунта ещё нет, пройдите регистрацию и выберите **тестирование платежей**. Если аккаунт уже есть: вверху нажмите блок с названием текущего магазина → **«Добавить магазин»** → **«Тестовый магазин»** → укажите вариант приёма «на сайте» и адрес **тестового** сайта → **«Добавить»**. Подождите появления нового магазина в списке и переключитесь именно на него. Эти подписи и последовательность описаны [ЮKassa](https://yookassa.ru/docs/support/merchant/payments/implement/test-store).

В выбранном **тестовом** магазине откройте **«Настройки» → «Магазин»** → скопируйте `shopId` в менеджер паролей с пометкой «тестовый». Затем **«Интеграция» → «Ключи API»** → выпустите/посмотрите секретный ключ **тестового магазина** и сохраните его там же. Не вставляйте его в production `.env`.

**В том же тестовом магазине:** слева **«Интеграция» → «HTTP-уведомления» → «Изменить настройки»**. В поле URL вставьте:

```text
https://api.stage.vpn.example.com/api/webhooks/yookassa
```

Замените домен своим staging API. Выберите события `payment.succeeded`, `payment.canceled`, `refund.succeeded` → сохраните настройки. Уведомления требуют доступного HTTPS-адреса; [официальное описание событий и настроек](https://yookassa.ru/docs/support/merchant/payments/http-notifications). Убедитесь, что поле URL **не** указывает на рабочий магазин.

## 8. В админке рабочего магазина заполните экран «Тестовый контур»

**В браузере:** откройте **рабочую** админку `https://admin.vpn.example.com`, войдите с 2FA → слева группа **«Продакшн» → «Тестовый контур»**. На экране **«Настройка боевого staging E2E»** заполните:

| Поле на экране | Что вводить |
| --- | --- |
| «Публичный HTTPS URL» | `https://api.stage.vpn.example.com` |
| «URL Remnawave» | URL **тестовой** панели |
| «Токен Remnawave» | API-токен **тестовой** панели |
| «Bearer-токен тестового пользователя» | токен отдельного staging-покупателя, если он подготовлен по процедуре проверки; **не** пароль администратора |
| «ID тестового тарифа» | номер `#` из пункта 6 |
| «ЮKassa — sandbox», «ID тестового магазина» | `shopId` именно тестового магазина |
| «Секретный ключ sandbox» | секретный ключ именно тестового магазина |

В строке с флажками оставьте отмеченной **только «ЮKassa»**; снимите «Platega» и «RollyPay», если их не проверяете. Поставьте галочку **«Подтверждаю sandbox-ключи»** → нажмите **«Сохранить безопасную конфигурацию»**. Если видите ошибку, перепроверьте тестовую Remnawave, тариф, URL и разделение ключей. Не вставляйте рабочий ключ, чтобы убрать ошибку.

Справа есть **«Запустить staging E2E»**. На `v20.0.18` этот runner проверяет только часть API-операций и **не открывает реальные платежи**. Если запустите его для диагностики, читайте итог, а не отдельные строки `[PASS]`: полный `full_e2e=true` не появится.

## 9. Где именно остановиться на v20.0.18

Откройте **«Безопасность» → «Безопасность»** в рабочей админке. Сейчас **«Разрешить реальные платежи»** отключена программно, рядом пояснение «Полный staging E2E v2 ещё не реализован». `POST /api/admin/payments/production-gate` с `enabled=true` вернёт HTTP 409. Даже на staging обычная внешняя тестовая покупка через `POST /api/payments/create` блокируется HTTP 503, пока нет допуска.

**Остановитесь здесь.** Не включайте кассу подменой ответа, прямой правкой `staging_e2e.status` или изменением frontend/backend. После выхода нового релиза проверьте, что в нём реализован **полный** runner v2, убрана блокировка кнопки, прошли CI и тесты на вашем staging. [Технические критерии для разработчика](STAGING_E2E_V2_IMPLEMENTATION.md).

## 10. Только после выпуска рабочего E2E v2: тестовая покупка

Этот раздел описывает **проверку будущего релиза**; названия кнопок могут измениться — сверяйте их с release notes. Не начинайте его на `v20.0.18`.

1. **В браузере:** откройте `https://cabinet.stage.vpn.example.com` → войдите как тестовый покупатель → выберите тестовый тариф → нажмите кнопку оплаты ЮKassa. Сохраните внутренний ID заказа и ID платежа ЮKassa в закрытом протоколе.
2. Оплатите на официальной **тестовой** странице только тестовыми данными из [инструкции ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing). Не вводите настоящую карту для тестового магазина.
3. **В тестовой админке:** «Продажи» → «Платежи» → найдите заказ по ID. Должен быть один оплаченный заказ и завершённая выдача. В тестовой Remnawave проверьте один доступ нужного пользователя и срок тарифа.
4. **В кабинете ЮKassa:** найдите тестовый платёж и доставку `payment.succeeded`. Один только возврат браузера на сайт не подтверждает оплату. Повторная доставка **того же** события не должна создать вторую подписку или финансовую запись.
5. Выполните возврат **через штатный маршрут магазина** для этого заказа. Если в разделе «Возвраты» появилась заявка, нажмите «Одобрить» и дождитесь завершения; эта кнопка сама по себе не доказывает возврат. Сверьте возврат в ЮKassa, «Финансовом журнале» и отзыв доступа в Remnawave. Без подтверждённого возврата и отзыва результата PASS нет.
6. Проверьте, что сам сервер записал `status=passed`, `contract_version=2`, `full_e2e=true`, текущую revision и время моложе 24 часов. Старый результат или изменение настройки требует полного повторного прогона.

## 11. Получите ключи настоящего магазина ЮKassa

**Только после пункта 10.** В кабинете ЮKassa переключитесь **с тестового** на **настоящий** магазин. Убедитесь, что рабочее подключение одобрено и его способы оплаты/параметры чеков согласованы с ЮKassa. В **«Настройки» → «Магазин»** возьмите рабочий `shopId`. В **«Интеграция» → «Ключи API»** нажмите **«Выпустить ключ»** для настоящего магазина, пройдите предусмотренное ЮKassa подтверждение и сохраните секрет в менеджере паролей. Тестовые и рабочие ключи разные; [официальный порядок ключей](https://yookassa.ru/docs/support/merchant/payments/implement/keys).

В **«Интеграция» → «HTTP-уведомления» → «Изменить настройки»** рабочего магазина задайте **рабочий** URL `https://api.vpn.example.com/api/webhooks/yookassa`, отметьте необходимые события и сохраните. Не оставляйте staging-адрес в рабочем магазине.

**В терминале рабочего VDS:** выполните `cd /opt/vpn-shop && sudoedit .env`; впишите рабочие `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в одноимённые строки. Проверьте `APP_ENV=production`, `PAYMENTS_SANDBOX=false`, `COOKIE_SECURE=true`, `DEFAULT_CURRENCY=RUB`, `WEBHOOK_BASE_URL=https://api.vpn.example.com`. Сохраните файл; не показывайте его целиком в чате/логах. Проверьте конфигурацию `sudo docker compose --env-file .env config --quiet`, затем перезапустите backend/worker по инструкции **нового** релиза и снова проверьте `/health/ready`.

## 12. Включите допуск и проверьте одну настоящую покупку

**Только после полного PASS v2 и установки рабочего релиза.** В рабочей админке откройте **«Безопасность» → «Безопасность»** → кнопку **«Разрешить реальные платежи»**. Если она всё ещё неактивна или сервер отвечает 409, остановитесь. Убедитесь, что строка «Разрешение реальных платежей» показывает **«ВКЛ — разрешено»**.

Из отдельной учётной записи покупателя оформите **одну** настоящую покупку на минимальную допустимую вашим магазином и кассой сумму. Это реальное списание: после него сравните статус и сумму в кабинете ЮKassa, таблице «Платежи», «Финансовом журнале» и Remnawave. Выполните и сверьте штатный возврат. Если сумма/ID/подписка/возврат не совпадают, **«Безопасность» → «Заблокировать»** и разберите расхождение до продаж клиентам.

## 13. Каждый день после запуска

В рабочей админке проверяйте **«Продажи» → «Платежи»**, **«Возвраты»**, **«Финансовый журнал»**, **«Главное» → «Состояние системы»** и **«Безопасность» → «Бекапы»**. В кабинете ЮKassa смотрите не доставленные webhook и возвраты. На сервере: `cd /opt/vpn-shop && sudo docker compose ps`, затем `curl -fsS https://api.vpn.example.com/health/ready`. При неизвестном статусе сначала сверяйте ID операции у ЮKassa; не нажимайте оплату второй раз наугад.

## Если не работает

| Что видите | Что это означает и куда вернуться |
| --- | --- |
| DNS не показывает IP нужного VDS | Пункт 2: имена и A/AAAA в панели регистратора |
| Не открывается `https://admin...` | Пункт 4/6: DNS, TCP 80/443, сертификат Caddy, `docker compose ps` |
| Тестовый ключ не сохраняется | Пункты 7–8: выбран именно тестовый магазин, верные поля, отдельная Remnawave |
| В runner есть `[PASS]`, но оплата недоступна | Пункт 9: v1 не равен полному E2E v2 |
| Кнопка «Разрешить» серая / ответ 409 | На v20.0.18 ожидаемо; после нового релиза проверьте полный PASS v2, текущую revision и срок 24 часа |
| Checkout возвращает 503 | Gate закрыт, либо платежи выключены/идёт техрежим; на staging v20.0.18 внешняя касса также блокируется |
| Списали деньги, VPN не выдан | Не создавайте новый платёж: найдите ID в ЮKassa, платёж в админке, ошибку выдачи и Remnawave; остановите новые продажи до сверки |
| Возврат виден только в одном месте | Не объявляйте цикл завершённым: проверьте статус у кассы, журнал и отзыв доступа |
