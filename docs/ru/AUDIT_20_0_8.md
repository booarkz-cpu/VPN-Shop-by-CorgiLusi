# Аудит v20.0.8 — 25 сентября 2026

## Вывод

Проверка проекта выявила подтверждённый риск ложного допуска платежей: runner считал чтение статуса провайдера, повторное чтение и возврат достаточным доказательством полного E2E, но не наблюдал webhook и выдачу VPN. Версия 20.0.8 перестаёт объявлять такой результат полным и использует новый ключ платежного допуска. Старый статус `passed` не проходит новый контракт. До реализации настоящего E2E включение живых платежей через админку закрыто.

| Область | Изменение | Ограничение |
| --- | --- | --- |
| Платежи | Недостоверный `FULL_E2E_PASS` удалён из runner; требуется контракт v2, новый ключ закрывает старый допуск | Нужна реализация проверки webhook, выдачи, повторной доставки и возврата |
| Образы | Стандартные Redis, PostgreSQL, Caddy, Python, Node и Nginx закреплены digest из Docker Registry | При обновлении образов требуется осознанно менять digest и проверять совместимость |
| Пароли | Compose передаёт Support Pro `POSTGRES_*`, SQLAlchemy собирает URL без ручной конкатенации | Вручную заданный backend `DATABASE_URL` требует percent encoding |
| Cookie | Backend отказывается запускаться в production при `COOKIE_SECURE=false` | Локальный test/staging может использовать HTTP только изолированно |
| Зависимости | CI проверяет backend и Support Pro через `pip-audit`, три frontend через `npm audit` до публикации Docker | Сканирование зависит от доступности баз advisory и registry |
| Контейнеры | Текущие ограничения `no-new-privileges`, `cap_drop` и `read_only` сохранены; БД и Redis имеют постоянные тома | `read_only` для БД без отдельной схемы writable каталогов не вводился |

## Проверка и границы

Выполняются Python тесты, тесты Support Pro, сборка трёх интерфейсов, проверка Compose, синтаксиса и зависимостей. Наличие тестов и отсутствие найденных advisory не доказывают отсутствие уязвимостей. Живые кассы и Remnawave не проверялись на инфраструктуре владельца. Подробный ручной план — [STAGING_E2E_20_0_8.md](STAGING_E2E_20_0_8.md).

## Перед обновлением

Сделайте и проверьте резервную копию. Сверьте заказы, созданные до обновления, с провайдерами. После запуска убедитесь, что админка отказывает во включении production-платежей, пока нет полного E2E v2. Не переносите старый ключ `payments.production_gate` в новый. Следите за webhook, очередями, выдачей, возвратами и журналом аудита.
