# Обновление VPN Shop до актуальной версии v20.0.28

Эта инструкция предназначена для **уже установленного VDS**. Она обновляет приложение на последний опубликованный GitHub-релиз и не требует повторной установки сервера.

> **Важно:** не выполняйте `docker compose down -v`. Эта команда удаляет Docker volumes и может удалить рабочую базу.

## 1. Что нужно перед обновлением

Перед началом:

- доступ по SSH к VDS;
- рабочая установка в `/opt/vpn-shop`;
- свободное место на диске;
- резервная копия базы и файлов вне VDS;
- доступ к менеджеру секретов.

Проверьте состояние:

```bash
cd /opt/vpn-shop
sudo docker compose ps
sudo docker compose --env-file .env config --quiet
sudo docker compose exec -T backend alembic current
df -h /
```

Если API уже не работает, сначала восстановите работоспособность текущей версии или используйте раздел аварийного восстановления ниже.

## 2. Обязательно сохраните резервную копию

Сохраните **вне VDS**:

- `/opt/vpn-shop/.env`;
- `/opt/vpn-shop/.env.images`;
- `/opt/vpn-shop/support-pro/.env`;
- резервную копию PostgreSQL;
- необходимые пользовательские uploads.

Не публикуйте содержимое этих файлов в чат, GitHub Issues или логи.

Если в вашей инфраструктуре используется штатный backup, убедитесь, что последний backup завершился успешно и его можно восстановить на отдельном стенде.

## 3. Запустите штатное обновление

Основная команда:

```bash
cd /opt/vpn-shop
sudo bash scripts/update-from-github.sh
```

Скрипт:

1. обращается к GitHub за **последним опубликованным релизом**;
2. скачивает release ZIP и SHA-256;
3. проверяет контрольную сумму;
4. не доверяет произвольному архиву или произвольному commit `main`;
5. оставляет существующие `.env`;
6. перед заменой файлов создаёт snapshot текущей установки;
7. делает dump базы;
8. запускает `scripts/update.sh`;
9. при ошибке сборки использует предусмотренный rollback-механизм.

Cron для автоматического обновления этим скриптом не устанавливается.

## 4. Как обновиться именно до v20.0.28

Перед запуском убедитесь, что релиз **v20.0.28 опубликован и CI прошёл успешно**.

После команды обновления проверьте версию:

```bash
cd /opt/vpn-shop
grep -n 'APP_VERSION' backend/app/main.py
sudo docker compose ps
```

Ожидаемая версия:

```
20.0.28
```

Если панель содержит информацию о текущем релизе, она также должна показывать v20.0.28.

## 5. Проверка после обновления

Выполните:

```bash
cd /opt/vpn-shop
sudo bash scripts/doctor.sh
sudo docker compose ps
sudo docker compose --env-file .env config --quiet
sudo docker compose exec -T backend alembic current
```

Проверьте API:

```bash
curl -fsS https://api.ВАШ-ДОМЕН/health/ready
```

Затем вручную проверьте:

- вход в админ-центр;
- все основные страницы админ-центра;
- отсутствие чёрных страниц;
- переключение светлой/тёмной темы;
- кабинет покупателя;
- Telegram Mini App;
- Support Pro;
- выдачу уже существующей подписки;
- состояние нод/Remnawave;
- очередь фоновых задач;
- платежи и callback только в разрешённом тестовом контуре.

## 6. Что изменилось в v20.0.28

### Админ-центр

Визуальная система админ-центра приведена к стилю **Support Pro**:

- единая навигационная rail-панель;
- стеклянный верхний bar;
- одинаковые карточки и поверхности;
- единые кнопки и поля;
- общая типографика;
- светлая и тёмная темы;
- адаптивная мобильная навигация.

Функциональные разделы админ-центра сохранены.

### Чёрные страницы

Исправление предыдущего релиза сохранено:

- ошибки API не переиспользуют старое состояние страницы;
- ошибки React-раздела перехватываются Error Boundary;
- вместо полного чёрного экрана показывается диагностическое сообщение.

## 7. Если обновление завершилось ошибкой

**Не запускайте обновление много раз подряд.**

Сначала соберите состояние:

```bash
cd /opt/vpn-shop
sudo docker compose ps
sudo docker compose logs --tail=200 backend worker caddy support_pro
sudo test -f .rollback/RECOVERY_MODE && sudo cat .rollback/RECOVERY_MODE
df -h /
```

Не публикуйте секреты из `.env` или токены из логов.

Если скрипт сообщил, что rollback активирован, сначала проверьте состояние восстановленной версии:

```bash
sudo bash /opt/vpn-shop/scripts/doctor.sh
sudo docker compose ps
```

Если автоматическое восстановление не завершилось, остановите изменения и восстанавливайте backup на отдельном стенде. Для production не выполняйте экспериментальные SQL-команды поверх единственной рабочей базы.

## 8. Если установка находится не в /opt/vpn-shop

Используйте переменную `APP_DIR`:

```bash
cd /ВАШ/КАТАЛОГ
sudo env APP_DIR=/ВАШ/КАТАЛОГ bash scripts/update-from-github.sh
```

Скрипт ожидает существующий `.env` внутри этого каталога.

## 9. Если SSH нестабилен

Используйте tmux:

```bash
sudo apt-get install -y tmux
tmux new -s vpn-update
cd /opt/vpn-shop
sudo bash scripts/update-from-github.sh
```

После обрыва SSH:

```bash
tmux attach -t vpn-update
```

## 10. Что нельзя делать

Не делайте:

```bash
docker compose down -v
```

Не удаляйте `/opt/vpn-shop/.env`.

Не заменяйте production `.env` файлом `.env.example`.

Не запускайте случайный commit из `main` вместо опубликованного release.

Не включайте реальные платежи только потому, что обновление прошло успешно.

## 11. Финальный чек-лист

- [ ] backup сохранён вне VDS;
- [ ] `docker compose config --quiet` проходит;
- [ ] обновление завершилось без ошибки;
- [ ] версия показывает v20.0.28;
- [ ] `doctor.sh` проходит;
- [ ] `/health/ready` отвечает успешно;
- [ ] админ-центр открывается;
- [ ] все основные страницы открываются без чёрного экрана;
- [ ] Support Pro работает;
- [ ] кабинет и Mini App работают;
- [ ] фоновые worker-задачи работают;
- [ ] платежи не включены без отдельного staging E2E;
- [ ] backup после обновления запланирован/проверен.

При штатном обновлении повторная установка VDS не нужна.
