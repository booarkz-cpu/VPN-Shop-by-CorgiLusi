# Обновление существующего магазина

v21.0.0-alpha.1 является предварительным выпуском. Для ознакомления используйте отдельный стенд. Не запускайте обновление действующего магазина без резервной копии и проверки новой схемы.

## Перед обновлением

1. Запишите текущий commit/tag и способ развёртывания.
2. Убедитесь, что нет неопределённых платежей и выполняющегося восстановления.
3. Снимите резервную копию базы и файлов, проверьте чтение архива.
4. Сохраните серверный `.env` отдельно с ограниченным доступом; не добавляйте его в Git.
5. Проверьте свободное место и доступ к Docker/GitHub.
6. Если ранее использовались другие агенты, сохраните их credentials для сверки исторических операций. Новые оплаты через них будут недоступны.

```bash
cd /opt/vpn-shop
bash scripts/backup.sh
git status --short
git rev-parse HEAD
```

Если есть собственные изменения, перенесите их в отдельную ветку и сравните до обновления. Не используйте `git reset --hard` для их удаления.

## Выбрать предварительный выпуск

После резервного копирования и сохранения собственных изменений:

```bash
git fetch origin
git switch --detach v21.0.0-alpha.1
```

Тег фиксирует проверенный CI commit; `main` может изменяться после выпуска.

## Новые миграции

Миграция `0042_workspace_withdrawals` добавляет nullable `idempotency_key` и уникальность `(user_id, idempotency_key)` в `withdrawal_requests`. Старые строки сохраняются. Ключ защищает новые повторные заявки от второго резервирования баланса.

Миграция `0043_support_conversations` добавляет историю сообщений и уникальные ключи повторной отправки. Существующий последний ответ каждого оператора переносится в историю. Начальный вопрос остаётся в обращении; старые API-проекции сохраняются. До запуска нового backend обязательно примените все миграции до head.

Миграция `0044_subscription_commerce` добавляет пакеты трафика, неизменяемые расчёты/операции и стоимость дня подписки. Старые подписки сохраняются. Откат 0044 удаляет историю этих заказов: при наличии финансовых операций используйте исправление вперёд, предварительно экспортировав таблицы.

```bash
docker compose build backend worker bot admin cabinet miniapp
docker compose run --rm backend alembic upgrade head
docker compose up -d backend worker bot admin cabinet miniapp
docker compose ps
```

Проверьте фактическое имя сервиса backend в вашем compose. В действующем проекте Alembic находится в образе backend. Существующий штатный `scripts/update.sh` содержит резервирование и проверку состояния; для установки из релиза используйте его регламент. Простое скачивание `main` не является установкой нового опубликованного релиза.

## Что поменяется

- Меню админки сгруппировано по задачам; несколько старых обзорных страниц скрыты из обычной навигации.
- Карточка клиента выбирается из поиска, а не из заранее заданного пользователя №1.
- Кабинет получил страницы кошелька, платежей, подписки, подарков, рефералов, уведомлений и безопасности.
- Встроенные страницы объединяются по виду и slug; старое сохранённое меню получает недостающие основные страницы.
- Mini App использует общие исходники кабинета. Docker context Mini App теперь корень репозитория; его Dockerfile копирует `cabinet`.
- Локальная standalone-сборка Mini App требует зависимости кабинета.
- Новые агенты ограничены тремя; Apple/Google receipt checkout отключён.
- Сине-фиолетовая палитра применяется к веб интерфейсам и исходникам мобильных клиентов.
- Ответ на обращение создаёт уведомление клиента; точный повтор ответа не дублирует его.

## Проверка после обновления

Откройте админку и кабинет в новом приватном окне, чтобы не использовать старый JS из кеша. Проверьте вход, 2FA и CSRF. Создайте тестовый тариф, проведите покупку в sandbox, дождитесь выдачи доступа. Проверьте кошелёк, подарок, повтор активации, заявку на выплату и ответ поддержки. В Telegram проверьте `/account`, ссылку приглашения, переходы в страницы и кнопки Mini App.

Проверьте запросы `/api/payments/providers` и публичный конфиг. В коммерческом каталоге должны быть только `yookassa`, `rollypay`, `platega`. Тестовый sandbox показывается только на допустимом окружении. Старые payment records должны оставаться в истории.

## Мобильные приложения

Изменения исходников не обновляют APK/IPA, уже установленные у пользователей. Для новых цветов и функций соберите, подпишите и распространите новые клиентские и административные приложения по мобильной инструкции. CI проверяет Android/iOS отдельно. Apple/Google встроенные покупки теперь закрыты сервером, даже если старый клиент пытается их вызвать.

## Откат

Остановите новые операции, сохраните состояние после обновления и сравните миграции. Если требуется downgrade, сначала оцените новые заявки с ключами: откат 0042 удаляет ключи, хотя сами заявки остаются. Откат 0043 удаляет всю новую переписку: сначала экспортируйте `support_messages`, если она нужна. Для финансовых данных предпочтительнее исправление вперёд. Для полного восстановления используйте проверенный дамп и штатный регламент; не подменяйте текущую базу старым дампом без анализа новых платежей.

## Локальная проверка разработчика

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt -r backend/requirements-test.txt
APP_ENV=test APP_SECRET=test-only-secret PYTHONPATH=backend .venv/bin/python -m pytest -q tests
(cd admin && npm ci && npm run typecheck && npm run build)
(cd cabinet && npm ci && npm run typecheck && npm test && npm run build)
(cd miniapp && npm ci && npm run typecheck && npm run build)
```

SQLite-тесты новых проекций не проверяют PostgreSQL advisory locks. CI содержит отдельные PostgreSQL-регрессии, миграции, Compose и native-сборки. Для E2E реальной кассы необходим внешний стенд и корректные credentials.


Docker-публикация предварительного выпуска использует `preview`, тег ветки и SHA; стабильный `latest` не заменяется alpha-сборкой. Публикуются образы backend, bot, admin, cabinet и miniapp. Для воспроизводимого развёртывания закрепляйте image digest.
