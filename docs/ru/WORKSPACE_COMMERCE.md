# Смена тарифа и дополнительный трафик

В предварительном выпуске v21.0.0-alpha.1 работает оплата с внутреннего кошелька. При недостатке средств сначала откройте «Кошелёк» и пополните баланс через разрешённого агента. Внешние платежи требуют отдельного подтверждённого E2E; production gate не обходится.

## Пользователь

1. Откройте «Подписка». Нужна действующая подписка с конечным сроком.
2. Выберите новый фиксированный тариф или дополнительный пакет трафика.
3. Нажмите «Рассчитать доплату». Сравните трафик, устройства, сумму и срок.
4. Подтвердите списание с кошелька. Расчёт действует 60 секунд до первого принятия заказа.
5. Обновите статус заказов. «Принят» ещё не означает применённые лимиты. Очередь отдельно обновляет Remnawave.
6. Если ответ потерян, повторите подтверждение того же расчёта. Повтор не списывает баланс заново, даже после истечения расчёта уже принятого заказа.

Срок подписки не продлевается. Для смены тарифа: `max(0, новая стоимость дня − прежняя стоимость дня) × оставшиеся дни`, округление вверх до копейки. Нулевая разница не превращается в деньги кошелька. Пакет оплачивается по фиксированной цене и увеличивает общий лимит до конца срока. Безлимитным подпискам пакет не продаётся.

Стоимость дня новых оплаченных подписок сохраняется из фактической суммы и срока, включая бонусные дни. Для прежней подписки без сохранённой ставки используется последний завершённый платёж того же тарифа/валюты; при его отсутствии ставка нулевая. Бесплатные новые подарки не дают платёжного кредита. Исторические нестандартные начисления требуют сверки оператором перед сменой тарифа.

Снижение устройства ниже числа активных устройств отклоняется. Снижение трафика ниже уже использованного отклоняется; если Remnawave не возвращает использование, операция блокируется. Параллельная незавершённая операция не допускает новое списание.

## Администратор

В «Продажи → Пакеты трафика» создайте название, объём, цену, порядок и доступность. Пустой ID тарифа означает все тарифы. Отключение пакета запрещает новые расчёты; уже выданный действующий расчёт сохраняет цену и лимиты. Удаления записей с историей нет.

В «Продажи → Изменения подписок» видны последние 100 заказов, владелец, сумма, статус и изменения. Для полного возврата нажмите «Вернуть на кошелёк». Это внутренний возврат, он не отправляет деньги на банковскую карту.

Для заказа в очереди возврат отменяет выдачу. Для применённого или неопределённого заказа сервер сначала восстанавливает прежние абсолютные лимиты. Только после подтверждения возвращает деньги. Сбой оставляет `refund_pending` и не кредитует кошелёк. Повтор кнопки безопасен. Заказ с последующим изменением срока/тарифа/лимитов или истёкшей применённой подпиской требует ручной сверки. Если трафик уже превышает прежний лимит, автоматический возврат блокируется.

Права: чтение пакетов — `read`, редактирование — `manage_plans`, список заказов — `payments.read`, возврат — `payments.refund`. Изменения записываются в аудит; списание и возврат — в финансовый журнал.

## API и обслуживание

- `GET /api/me/subscription/commerce`: каталог владельца.
- `POST /api/me/subscription/quote`: `kind`, `plan_id` или `package_id`, необязательный `subscription_id`. API смены конструктора принимает полный набор ID опций; отдельной формы смены конструктора в этом выпуске нет.
- `POST /api/me/subscription/purchase`: `quote_id`, обязательный `Idempotency-Key`.
- `GET /api/me/subscription/operations`: последние 100 своих заказов.
- `GET/POST /api/admin/traffic-packages`, `PUT /api/admin/traffic-packages/{id}`.
- `GET /api/admin/subscription-operations`, `POST /api/admin/subscription-operations/{id}/refund`.

Реальные сетевые сбои проверяются на отдельном стенде. Автоматические тесты моделируют потерю ответа после удалённой записи, проверяют повтор лимитов, единственное списание/возврат, владельца, истечение расчёта и изменение подписки. PostgreSQL CI дополнительно проверяет одновременное принятие одного расчёта и миграцию 0044. Несколько подписок на один аккаунт пока не поддерживаются.
