# Ветки репозитория

`main` — основная ветка. Теги `v*` и `mobile-v*` обозначают выпуски; их нельзя удалять при чистке веток. Перед новым исправлением создавайте короткоживущую `fix/…` или `docs/…` от актуального `main`, запускайте CI и удаляйте ветку после включения результата.

На 28 сентября 2026 есть 18 удалённых служебных веток. `git branch -r --merged origin/main` **не** подтверждает включение ни одной из них. `git cherry` находит эквивалентный патч у шести (`audit/v20.0.11-payments`, `audit/v20.0.13-staging-e2e-guide`, `audit/v20.0.9`, `cleanup/obsolete-publish-artifacts`, `docs/real-payments-readme-guide`, `docs/staging-vds-e2e-operator-v20-0-18`). Для других веток это не доказывает ни наличие, ни отсутствие их изменений в `main`: при squash и последующих правках идентичность патча теряется.

Перед удалением каждой ветки:

1. Сравните её изменения с `main`: `git log --oneline main..origin/ИМЯ` и `git diff main...origin/ИМЯ`.
2. Сверьте PR и выпуск, в который попало исправление; при необходимости перенесите отсутствующую часть отдельным проверенным PR.
3. Проверьте, что CI зелёный и нет открытого PR или зависимого процесса.
4. Удалите ветку в GitHub. Сохраните тег релиза и ссылку на PR/коммит для истории.

В текущей проверке удаление веток не выполнено: автоматическая проверка отклонила выбор способа подтверждения входа в GitHub без выбора владельца. Основной код опубликован в `main`; статус веток остаётся прежним.
