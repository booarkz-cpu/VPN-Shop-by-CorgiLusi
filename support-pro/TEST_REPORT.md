# Проверка Support Pro 3.4 — 18 сентября 2026

## Результат

36 тестов пройдены (pytest, 27.12 секунды), 2 предупреждения зависимостей Starlette о deprecated API. Тесты выполнялись на SQLite с включёнными foreign keys, fakeredis и HTTP/Telegram-заглушками. Браузерный E2E и нагрузочная проверка PostgreSQL здесь не выполнялись.

Проверены:
- существующие отправка Telegram, вложения, частичная доставка, неопределённый результат, idempotency, unread, split, настройки, отчёты, 2FA, CSRF, WebSocket, AI;
- изоляция команд: тикеты, клиенты, сообщения, вложения, CSV и массовые операции; запрет изменения для viewer;
- отзыв серверной сессии;
- атомарный откат outbox; однократное применение правила и уведомления;
- подпись вебхука, стабильный Idempotency-Key, 8 попыток, dead-letter, восстановление просроченного lease;
- праздники, рабочая суббота, часовые пояса/DST, пауза SLA через выходные с сохранением рабочих часов;
- сохранённые фильтры, массовые теги, упоминания, обязательный просмотр объединения;
- создание веб-обращения, отправка ответа в портал без Telegram, скрытие заметок, запрет чужой истории, загрузка и скачивание вложения;
- подтверждение обновления инцидента и отсутствие повторной постановки в очередь;
- протокол сканера: clean/infected и отказ без обязательного антивируса;
- маршруты календарей, валидация правил;
- миграции с нуля, с исходной 2.1 и с 3.3 с сохранением данных; защита неизвестной unversioned-схемы.

Python/шаблоны Jinja разобраны; JavaScript и shell-скрипты проверены на синтаксис; YAML Compose проверен, включая volumes backup/antivirus.

## Что требует сервера

Docker, PostgreSQL, живой Redis, ClamAV и браузер Chromium в окружении не доступны. Поэтому не подтверждены: реальная работа GIN-индексов PostgreSQL, конкурентные SKIP LOCKED под нагрузкой, живое антивирусное сканирование, внешний webhook и Telegram, браузерная адаптивность/доступность, восстановление pg_dump. Скрипт restore-check.sh реализован и включён в backup, но настоящий restore drill нужно выполнить на сервере. Скрипт использует отдельную временную БД, проверяет SHA256 и наличие всех готовых вложений.

Не следует считать эту сборку прошедшей production acceptance без этих проверок. Перед миграцией нужна резервная копия; обновление инвалидирует старые сессии. Антивирус по умолчанию выключен до настройки ClamAV; обязательный режим блокирует загрузки при его недоступности. История клиента открывается по секретной ссылке, не по проверенному email.
